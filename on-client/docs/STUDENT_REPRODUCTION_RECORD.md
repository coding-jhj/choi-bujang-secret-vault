# 재현 가능한 최종 인수인계 (STUDENT_REPRODUCTION_RECORD)

22단계 결과물입니다. 같은 최종 커밋을 **완전히 새로운 폴더**에서 처음부터 다시 받아 실행해 보고, 그 증거를 남긴 기록입니다. 이 기록은 **학생 진술**입니다 — 판정 AI가 아래 명령을 대신 실행해서 확인한 것이 아니라, 제가(학생 Agent) 실제로 실행하고 그 결과를 그대로 옮긴 것입니다.

```
$ git -C <새 폴더>/repo rev-parse HEAD
392e56e3040955bc3667355e9989b4c5c4370e77
```
→ 목표 커밋과 정확히 일치 확인.

**런타임 확인** (실행함, RUNBOOK 1절 절차):

**설치·구문 검사** (실행함):
```
$ npm --prefix <새 폴더>/repo/on-client run check
> node --check student/extension.mjs
EXIT_CODE=0
```
`node_modules`는 생성되지 않았습니다(`dependencies` 없음 — `npm install` 불필요, RUNBOOK 1절과 일치).

**실행 및 브라우저(HTTP) 확인** (실행함, 포트 충돌 방지를 위해 `ON_PORT=5199` 사용):
```
$ ON_PORT=5199 npm --prefix <새 폴더>/repo/on-client run demo
케셰브 예제: http://127.0.0.1:5199
$ curl -i http://127.0.0.1:5199/
HTTP/1.1 200 OK
content-type: text/html; charset=utf-8
... (학생 페이지 HTML 정상 수신)
```
→ RUNBOOK 5절이 서술한 시작 메시지 패턴과 정확히 일치(포트 번호만 치환). HTTP 200 응답으로 "브라우저로 접속 가능함"을 확인했습니다(이번 재현에서는 화면 캡처 대신 HTTP 응답 확인으로 대체).

**종료 및 재실행** (실행함 — 중요한 발견 포함):
```
(작업 중지 요청) → 배경 작업은 멈췄지만
$ curl -i --max-time 5 http://127.0.0.1:5199/
HTTP/1.1 200 OK   ← 여전히 응답함(예상과 다름)
$ netstat -ano | grep 5199
TCP 127.0.0.1:5199 LISTENING <PID>
```
**발견**: 배경 작업(셸)만 멈췄을 뿐, 실제로 포트를 들고 있는 `node.exe` 프로세스는 고아 프로세스로 남아 계속 응답했습니다. `netstat`으로 실제 PID를 찾아 `Stop-Process -Force`로 직접 종료해야 완전히 멈췄습니다:
```
$ Stop-Process -Id <PID> -Force
$ curl -i --max-time 5 http://127.0.0.1:5199/
curl: (7) Failed to connect ... Could not connect to server   ← 완전히 종료됨
```
이건 RUNBOOK 6절이 코드 근거(`SIGINT`/`SIGTERM` 핸들러 없음)로 미리 경고했던 내용이 **실제로 재현된 사례**입니다. **RUNBOOK의 종료 안내에 이 내용을 보완할 필요가 있습니다**(아래 6절 "미해결 사항" 참고).

재실행도 같은 포트로 정상 확인했습니다(두 번째 `npm run demo` → HTTP 200 → 같은 방식으로 종료).

**재현 폴더 절대 경로**(삭제하지 않고 보존): 세션 스크래치패드 하위 `repro-392e56e/repo` — 원본 프로젝트 밖의 임시 작업 영역입니다.

**한계**: 조치 DB의 "삭제 경로가 코드에 없다"는 건 설계상 의도(데이터 무결성 보장, `src/actions/README.md`에 명시된 정책)로 보이지만, 그 말은 **한번 쌓인 조치 기록은 운영자가 OS 수준에서 파일을 직접 지우는 것 외에는 지울 방법이 없다**는 뜻이기도 합니다. 실제 운영 환경에서 이게 받아들여질 보존 정책인지는 운영자가 판단할 문제입니다.

## 4. 시연과 학생 진술 구분

이 기록 전체에서 사용한 확인 수준을 명확히 구분합니다:

| 수준 | 뜻 | 이 기록에서 해당하는 부분 |
|---|---|---|
| **실제 실행 검증** | 제가 직접 명령을 실행하고 원문 출력을 받음 | 1절의 clone/버전/구문검사/서버 기동/HTTP 응답/종료-재실행 전부. 17~20단계의 Node 직접 실행 케이스들 |
| **코드 확인(읽기)** | 소스 코드를 읽고 동작을 판단했으나 실행하지 않음 | 포트 충돌 시나리오, Node 버전 범위 밖 시나리오, 조치(action) DB의 삭제 제한, 자격증명 암호화 방식 |
| **학생 진술(이 문서)** | 위 둘을 종합해 제가 작성한 기록 | 이 문서 전체 |
| **AI 원문 검토(서버 판정)** | 판정 AI가 이 커밋의 코드·문서를 읽고 일치 여부만 판단 — 실행하지 않음 | 제출 후 서버가 수행 (이 기록이 "실행 성공 증명"이 아님을 분명히 합니다) |

**AI 원문 검토를 실행 성공 증명으로 표현하지 않습니다**: 17~20단계의 실제 `ok`/`succeeded` 상태(AI 연결 성공, 조치 실제 집행)는 운영자 측 설정이 끝나야 재현 가능하며, 이번 22단계 재현에서도 확인하지 못했습니다. 이 기록은 "코드가 설계대로 동작한다"는 것까지를 증명하며, "실제 운영 환경에서 전부 연결됐다"는 증명이 아닙니다.

## 5. 이동 가능한 구성

- `on-client`는 외부 npm 의존성이 없어 다른 PC로 옮겨도 `npm install` 없이 바로 `npm run demo`/`npm run check`가 됩니다(이번 재현에서 실제로 확인).
- 설정 키는 전부 `on-client/.env.example`에 예시로 있습니다(`ON_PORT`, `ON_ENGINE_ADAPTER`, `ON_AI_MODEL`, `ON_PROJECT_DIRECTORY`, `ON_APPROVED_PUBLIC_PACKAGES`). 실제 비밀값이 필요한 키(`ON_AI_BASE_URL`, `ON_AI_APP_KEY` 등)는 예시 파일에 없고, 운영자가 별도로 주입합니다.
- 코드 안에 로컬 절대경로 하드코딩은 없습니다(조치 DB 경로·vault 경로는 전부 운영자가 CLI 인자/설정 파일로 주입하는 구조).
- 다만 제공 PowerShell 실행 도구(`tools/start-alekov.ps1`)는 Windows 전용입니다(코드 확인, 이번 재현에서는 `npm` 명령으로 직접 실행해 이 도구 자체는 쓰지 않았습니다).

## 6. 버전과 지원 범위

- 검수 기준 Node.js: `24.19.0`(정확 고정값). 실제 확인 범위: `22~24`(제공 실행 도구 기준, 그 밖은 실행 도구가 차단).
- 외부 npm 의존성 없음.
- Windows + PowerShell 5.1 이상 필요(제공 실행 도구 기준). macOS/Linux 동작은 확인하지 않았습니다.
- **누락·미해결 사항** (지어내지 않고 정확히 적습니다):
  1. `Ctrl+C`/작업 중지만으로 서버 프로세스가 완전히 안 죽는 문제(1절에서 실제로 재현·확인) — RUNBOOK 보완 필요.
  2. AI 연결 실제 성공(`ok`), 조치 실제 집행(`prepared` 이후), 패키지 취약점 실제 조회(`complete`/`partial`)는 전부 운영자 측 설정이 끝나야 재현 가능하며, 이번 22단계까지도 재현하지 못했습니다("검증 중인 버전"이며 v1.0 자동 인증이 아닙니다 — 과제 안내문과 동일한 입장).
  3. `aleph.config.json`의 `step` 값이 `17`로 남아 있어, 실제 진행(21단계까지 완료)과 어긋납니다 — **누적 원문 일관성 공백**으로, 사용자 확인 후 갱신이 필요합니다.
  4. 자격증명 vault의 삭제 함수가 정의만 있고 실제 호출 경로를 찾지 못했습니다 — 삭제가 실제로 동작하는지는 미확인입니다.

## 7. 확인하지 못한 것 (이 기록 자체에 대해)

- 완전히 다른 물리 PC/네트워크 환경에서의 재현은 하지 않았습니다(같은 PC의 새 폴더에서만 재현).
- `tools/start-alekov.ps1`(제공 PowerShell 도구) 자체는 이번 재현에서 실행하지 않았습니다(npm 명령으로 직접 실행).
- 22단계는 아직 공식 제출 전이라 AI 판정 결과가 없습니다.
